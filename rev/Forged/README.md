# Forged — self-forging code / hash-to-shellcode stage

A password lock with **no key check in it**. The input's MD5 digests are written
into an executable page and *called*; the only key whose digests assemble into a
valid call to the hidden flag-printer wins. The real verdict exists only as code
manufactured at runtime from the player's own input.

## Files

| File             | Purpose                                                               |
|------------------|-----------------------------------------------------------------------|
| `task.c`         | The challenge source (compiled to `dist/forge`). Anti-debug gate, per-chunk MD5, mmap+call, hidden `reveal`. |
| `solve.c`        | Author brute-forcer (OpenMP): finds each 4-byte chunk that forges the target bytes. |
| `solve.py`       | Pure-Python replay/verifier of the full pipeline (chunk → MD5 → shuffle). |
| `build.py`       | Builds everything, derives the key, verifies it, and stages `dist/`.  |
| `generated.h`    | Generated by `build.py`; `#include`d by `task.c` (suffixes, POS, MAGIC, encoded flag). |
| `answer.txt`     | Generated: KEY / MAGIC / &reveal / POS / target / FLAG for this build. |
| `dist/forge`     | The shipped, stripped binary.                                         |
| `dist/challenge.txt` | Player-facing prompt.                                             |

**Ship to players:** `dist/` only. **Keep private:** everything else
(`task.c`, `solve.*`, `build.py`, `generated.h`, `answer.txt`, `*.unstripped`).

## Build & test

```sh
# full build: writes generated.h, compiles forge, brute-forces the key,
# verifies it in Python AND against the real binary, then strips into dist/
python3 build.py

# re-roll the challenge
FLAG='SecurinetsENIT{...}' python3 build.py     # different flag
MAGIC=0xDEADC0DE          python3 build.py       # different magic argument
SEED=0x1234               python3 build.py       # different suffixes / positions
```

The anti-debug gate (`ptrace(PTRACE_TRACEME)`) blocks `strace`/gdb, so to run the
binary outside the grader, preload a stub that neutralises `ptrace`:

```sh
echo 'long ptrace(int r,int p,void*a,void*d){return 0;}' > stub.c
gcc -shared -fPIC -o stub.so stub.c
LD_PRELOAD=./stub.so ./dist/forge
key: <32 hex digits from answer.txt>
-> The lock forges its own key and swings open:  <flag>
```

Verify the intended key without the binary:

```sh
python3 solve.py          # reads generated.h + answer.txt, confirms MATCH
```

## How it works (one paragraph)

The 16-byte key is four 4-byte chunks. Each chunk is appended to a fixed 8-byte
suffix and MD5'd; three bytes of each digest (positions `POS`) are copied into an
`mmap(PROT_EXEC)` page, and the page is called. The correct key is the one whose
twelve forged bytes spell `mov edi, MAGIC ; mov eax, &reveal ; jmp rax`, i.e.
`reveal(MAGIC)`, which decodes and prints the flag. Built `-no-pie` so `&reveal`
is a fixed 32-bit immediate; the flag is stored XOR'd with a MAGIC-seeded
keystream so it never appears in `strings`. Wrong keys forge garbage and are
caught by a SIGSEGV/SIGILL handler as a plain `nope.`. Full writeup in
[`solution.md`](solution.md).

## Requirements

- Linux with `PTRACE_TRACEME` allowed (a seccomp profile that forbids `ptrace`,
  e.g. some container defaults, makes the binary exit as if watched — run in a
  normal Linux / VM).
- Must stay `-no-pie` (the forged `mov eax,&reveal` uses an absolute 32-bit
  address).
